# Reference comparison worksheet

Use only the dimensions relevant to the request. Record observed values and unknowns rather than inventing precise measurements.

| Area | Reference observation | Intended adaptation | Actual render | Remaining difference |
| --- | --- | --- | --- | --- |
| Header | Height, logo, menu, main action | Target brand and actual navigation | Matching viewport and state | State the difference |
| Hero | Image crop, text axis, width and fold | Real assets and specific copy | Compare corresponding crop | Fix geometry before minor color tweaks |
| Internal page | Content/aside relationship | Required page family and content | Follow one real navigation path | Note missing functionality |
| Mobile | Menu, stacking, sticky action | Same task in smaller space | Narrow-width interaction | Note device/input limits |
| Main form | Steps, validation and result | Supported local or server-backed flow | Exercise state transitions safely | Never label local-only data as sent |

If a user rejects a result for being visually distant from a reference, adding more pages does not resolve that defect. Revisit the first viewport, image treatment, typography and content density. Conversely, matching one hero does not complete a full-site request.

Use independent target-brand implementation and assets. Keep public reference analysis separate from redistribution rights and unavailable backend behavior.
